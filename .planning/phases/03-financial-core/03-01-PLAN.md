**Phase goal:** Track payments, generate invoices, provide financial overview with Excel export.

**Requirements addressed:**
- FIN-01: Record income payments (rent, deposits)
- FIN-02: Record expense payments (maintenance, utilities)

**Key decisions (from CONTEXT.md):**
- D-01: Both lease-linked and standalone payments supported
- D-02: Default linked to lease (auto-populated rent amount)
- D-03: Standalone for deposits, manual adjustments
- D-04: Payment types: Rent, Deposit, Late Fee, Water (SYABAS), Electricity (TNB), Internet, IWK, Maintenance, Legal Fees, Agent Commission, Renovation, Insurance, Quit Rent, Assessment, Other
- D-05: Deposits tracked separately in trust, never set-off with rent

**Payment model fields (from schema.prisma):**
- type: income | expense
- amountSen: Int (stored in sen)
- description: String?
- referenceNumber: String? (receipt number)
- paidAt: DateTime?
- dueDate: DateTime?
- status: pending | paid | overdue | cancelled
- leaseId: String? (optional link)
- tenantId: String? (optional link)
- category: String? (LHDN expense category)

**Create `src/services/payment-service.ts`:**

1. Create `PaymentService` class with:
   - `createPayment(data)`: Create payment, handle lease linking, generate reference if not provided
   - `getPayments(filters)`: List with filtering (type, status, date range, tenantId, leaseId)
   - `getPaymentById(id)`: Single payment with relations
   - `updatePayment(id, data)`: Update payment
   - `deletePayment(id)`: Soft delete
   - `getPaymentStats(userId)`: Aggregated stats for dashboard

2. Create API routes:
   - `GET /api/v1/payments` — List with query filters (?type=income&status=pending&tenantId=xxx)
   - `POST /api/v1/payments` — Create payment
   - `GET /api/v1/payments/[id]` — Get single
   - `PUT /api/v1/payments/[id]` — Update
   - `DELETE /api/v1/payments/[id]` — Soft delete

**Payment creation logic:**
- If leaseId provided: auto-populate tenantId from lease
- Auto-generate reference: `RCP-YYYYMMDD-XXXX` format if not provided
- Set status to 'paid' if paidAt is set, 'pending' if dueDate in future, 'overdue' if dueDate passed
